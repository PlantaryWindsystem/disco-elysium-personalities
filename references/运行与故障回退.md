# 运行与故障回退

在主动检定、运行时故障或核对结果来源时读取。本文件统一主说明与检定系统的执行例外；不改变人物卡、思维修正、掷骰公式或用户确认要求。

## 正常路径

1. 先选择人格与当前心智动作，确定目标值和有事实依据的修正。`runtime_context.py context` 负责人格资料、被动检定和思维审计；`checks` 只放被动检定。
2. 若返回 `review_required=true`，先完成语义复核并按主说明同轮重试。主动检定放在最后一次 context 调用之后，避免复核重试造成重新掷骰。
3. 主动检定使用 `python scripts/check_engine.py active --skill <人格名> --dc <目标值>`，按需传入 `--condition`、`--modifier`。需要模拟测试时，显式传入测试用 `--sheet`、`--thoughts` 与 `--no-log`，不接触个人状态。
4. 保存最后一次 context 返回的 JSON；将本轮主动结果原样追加到其 `checks` 列表，保留 `candidate_attributes` 等原有字段。只合并当前用户轮记录。一个心智动作只掷一次，排版修改不重掷；同一人格重复发言可引用同一动作结果，真正的新动作才重新确定检定。
5. 用合并后的 JSON 核对输出标题，并将它传给 `validate_output.py --runtime-json`。索引提供名字和颜色，计算结果提供难度、成功/失败；索引本身没有本轮检定结论。

## 受限故障回退

- **索引不可用、检定脚本可用**：读取选中人格的参考资料，使用 `check_engine.py passive` 或 `active`。把本轮结果整理为包含 `checks` 列表与真实候选属性的 JSON；不伪造思维审计或推进计数。
- **检定脚本不可用、状态可核实**：仅被动检定允许手算，优先用可用计算工具复核。先读取有效人物卡和当前思维状态，逐项计算基础值、思维修正、情境修正、目标值与总值。保留本轮算式及来源，按下列格式记录；不能根据希望的成败回填数值。
- **人物卡缺失或无效**：按人物卡向导及异常规则处理，不猜测基础值。已有思维文件损坏或有效修正无法确认时，暂停依赖这些数值的检定，不把未知修正当零。
- **主动检定无法取得真实骰面**：暂停主动检定并说明故障，不手写骰面，不自动改成被动结果。
- **格式校验器不可用**：人工逐项核对官方名字、颜色、难度、结果、段落和声纹，并核对本轮算式；只能说明人工复核，不能宣称脚本通过。
- 故障不能阻止必要事实与安全信息。需要时用简明普通回复说明状态和可靠内容，不伪装成人格检定。

被动回退记录结构（尖括号需替换为实际数据，不能原样作为结果）：

```text
mode: manual-passive-fallback
turn_key: 当前用户轮标识
candidate_attributes: 本轮确有贡献的候选属性列表
checks: 每项包含 skill、difficulty、dc、base、thought_modifiers、thought_total、effective_skill、situational_modifiers、situational_total、constant=6、total、success
```

写成 JSON 时 `success` 必须是布尔值。保留 `total = 6 + effective_skill + situational_total`，并按 `total >= dc` 求得结果。格式检查只验证所提供记录与文本的一致性，真实来源和算式仍需复核。

多属性候选经语义复核后最终仅保留一个属性时，不修改原始候选记录。在本轮 JSON 的 `routing_review.excluded_attributes` 中，按被省略属性填写具体候选与淘汰理由，例如 `{ "智力": "逻辑思维拟加入的推断已由另一声音表达，没有独立线索。" }`。现有校验会检查被省略属性是否都有理由；理由是否成立仍由语义复核判断，不能用无意义文字放行。不同人格按名字去重计数，同一声音重复出场不算多个不同人格。

## 维护与打包

维护、检查和打包不启动角色模式。`package_skill.py` 仅收录主文件、许可证及 references、scripts、assets、agents 内的可分发内容，排除隐藏文件、备份、测试、缓存、旧包和根目录运行草稿。新增资源时先确认确为技能必需资料；个人状态和私人对话不得放入可分发资源目录。

本地打包不等于发布。保留旧包，使用新的输出文件名，打开新包核对文件清单和必需资源。规则修改前保存备份；新增备份宜位于技能发现目录之外，避免同名 SKILL.md 重复出现。已有备份按用户的保留要求处理。
